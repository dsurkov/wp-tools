# WP Tools

**WP Tools — набор CLI-инструментов для обслуживания WordPress**

```bash
curl -sSL https://gist.githubusercontent.com/dsurkov/efafe42477aa571139401628d2fafd5a/raw/wp-tools.php | php -- packager woocommerce
```

## Что это / для чего

Stateless-набор CLI-инструментов для админа множества сайтов: один
самодостаточный PHP-файл, который запускается прямо на сервере WordPress
(через `curl | php`, установленный исполняемый файл или функции в shell-сессии),
находит WP-инсталляцию по `wp-load.php` и выполняет обслуживающие операции.
Ничего не устанавливается в сам WordPress: код живёт только в процессе PHP.

## Инструменты

| Инструмент  | Статус   | Описание                                        |
|-------------|----------|-------------------------------------------------|
| `packager`  | Доступно | Пакует установленные плагины и темы в ZIP-архивы и выдаёт download-ссылки |
| `backupper` | Доступно | Бэкап файлов сайта и дампа БД в один ZIP-архив |
| `wp-info`   | Доступно | Стек и конфиг: версии, лимиты PHP, статусы, плагины, темы |
| `api`       | Доступно | Контекст REST API: локаль, аддоны, таблицы БД, кастомные namespaces, схемы таблиц |

## Установка / способы запуска

Все способы используют **один и тот же скрипт** — код не ветвится. Разница
только в том, как файл попадает в PHP. Запуск — из корня сайта или любой
поддиректории (корень WP ищется подъёмом вверх от текущей директории).

### Способ 1 (рекомендуется для постоянных сайтов): файл вне docroot

```bash
curl -sSL https://gist.githubusercontent.com/dsurkov/efafe42477aa571139401628d2fafd5a/raw/wp-tools.php -o /usr/local/bin/wp-tools
chmod +x /usr/local/bin/wp-tools
wp-tools packager woocommerce
```

Файл лежит **вне веб-корня** — веб-сервер его не отдаёт и не исполняет.
Обновление — повторный `curl -o` (или `git pull`, если положить файл в
репозиторий). Установленный файл можно один раз аудировать: он детерминирован
и не меняется между запусками.

### Способ 2 (разово / без установки): curl | php

```bash
curl -sSL https://gist.githubusercontent.com/dsurkov/efafe42477aa571139401628d2fafd5a/raw/wp-tools.php | php -- packager woocommerce
```

Ничего не пишется на диск. Удобно для одноразовых операций и демо; для
прод-сайтов предпочтителен Способ 1 (см. «Безопасность»).

### Способ 3 (интерактивные сессии): функции в shell с таб-дополнением

```bash
eval "$(curl -sSL https://gist.githubusercontent.com/dsurkov/efafe42477aa571139401628d2fafd5a/raw/wp-tools.sh)"
```

Один раз загрузили — и в текущей сессии доступны функции (`wp-*` подставляются
табом, как обычные команды):

| Функция            | Эквивалент                     | Таб подсказывает        |
|--------------------|--------------------------------|-------------------------|
| `wp-tools`         | `wp-tools.php` (диспетчер)     | инструменты, флаги      |
| `wp-packager`      | `packager …`                   | флаги + слаги (нужен WP-CLI) |
| `wp-backupper`     | `backupper …`                  | `--list`, `--help`      |
| `wp-info`          | `wp-info`                      | `--help`                |
| `wp-api-context`   | `api …`                        | `--help`                |
| `wp-api`           | алиас `wp-api-context`         | —                       |

Подсказка слагов в `wp-packager` берётся из WP-CLI (`wp plugin list` /
`wp theme list`), если он установлен; без него — только флаги. Для
постоянного использования добавьте строку в `~/.bashrc`:

```bash
echo 'eval "$(curl -sSL https://gist.githubusercontent.com/dsurkov/efafe42477aa571139401628d2fafd5a/raw/wp-tools.sh)"' >> ~/.bashrc
```

Работает в bash и zsh (для zsh загрузчик сам включает `bashcompinit`).

## Использование

Верхнеуровневые команды:

| Команда             | Действие                                  |
|---------------------|-------------------------------------------|
| `packager <slug>`   | Запаковать плагин/тему по слагу           |
| `backupper`         | Бэкап файлов и БД в ZIP                   |
| `backupper --list`  | Список существующих бэкапов               |
| `wp-info`           | Информация о стеке и конфиге              |
| `api`               | Контекст REST API                         |
| `api <search>`      | Схема таблиц, содержащих `<search>`       |
| `list`, `-l`        | Показать доступные инструменты            |
| `help`, `-h`        | Показать справку                          |

Флаги `packager`:

| Флаг        | Действие                                        |
|-------------|-------------------------------------------------|
| `--list`, `-l` | Показать установленные плагины и темы       |
| `--all`, `-a`  | Запаковать все плагины и темы               |
| `--help`, `-h` | Справка по packager                         |

## Возможности

### packager

- Поиск корня WordPress подъёмом от текущей директории — работает из любой поддиректории сайта.
- Список установленных плагинов и тем со слагами и версиями.
- Упаковка по слагам, всех сразу (`--all`) или по списку слагов.
- Архивы кладутся в `_packages/` внутри корня WP — веб-доступная папка.
- Для каждого архива печатается прямая download-ссылка (`site_url()/_packages/<slug>-<version>.zip`).
- Slug в имени архива очищается от недопустимых символов; пустая версия → `0.0.0`.

### backupper

- Файлы сайта (весь корень WP) + дамп БД в одном ZIP внутри `_backups/`.
- Дамп БД чисто-PHP (без `mysqldump`): `SHOW CREATE TABLE` + `INSERT`, корректное экранирование, `SET FOREIGN_KEY_CHECKS` для InnoDB.
- Исключаются служебные папки (`_backups/`, `_packages/`) и dot-каталоги (`.git`, `.svn`); корневые dot-файлы (`.htaccess`) сохраняются.
- `backupper --list` показывает существующие бэкапы с размером и download-ссылками.
- Имя архива `backup-<дата>-<время>.zip`, внутри — `db-<дата>-<время>.sql`.

### wp-info

- Версии: WordPress, PHP, БД (MySQL/MariaDB), признак Multisite.
- Лимиты PHP (memory, upload) из CLI или из web-конфига (LiteSpeed/fpm/apache2), если найден.
- Статусы: WP_DEBUG, объектный кэш, режим cron (WP-Cron/Server).
- Локаль, таймзона, префикс и charset БД, пути WP и PHP-бинаря.
- Активные плагины и активная тема (с родительской, если тема — child).

### api

- Без аргументов: локаль/время, аддоны Bookly, таблицы БД (с количеством строк, без префикса), кастомные REST namespaces.
- С аргументом: схема всех таблиц, содержащих маску — колонки, типы, ключи (PRI/MUL подсвечены), доп. атрибуты.

## Требования

- **PHP 7.2+ (CLI)** — скрипт проверяет версию и завершается с понятной ошибкой на старых PHP.
- Расширение **ZipArchive** — для `packager` и `backupper` (проверка: `php -m | grep -i zip`).
- **curl** — для Способов 2 и 3.
- **SSH-доступ** к серверу.
- **WP-CLI** (`wp`) — опционально, только для таб-подсказки слагов в `wp-packager`.

> Важно: CLI-версия PHP на cPanel-хостингах может отличаться от веб-PHP
> (версия, набор расширений). Проверяйте именно CLI: `php -v`,
> `php -m | grep -i zip`.

## Подводные камни

- **CLI-php ≠ веб-php**: на shared-хостинге `which php` покажет CLI-бинарь; веб-PHP может иметь другие расширения. Расширения проверяются у runtime-CLI, а не у веб-PHP.
- **CLI без ZipArchive**: `packager`/`backupper` честно сообщают об ошибке — проверяйте `php -m | grep -i zip` заранее.
- **`--` обязателен** при `curl | php`: `php -- packager …` — иначе `packager` будет воспринят как аргумент самого php.
- **`source <(...)` не везде работает**: на некоторых сборках bash пайп не читается — используйте `eval "$(curl -sSL …)"`.
- **Большие сайты**: упаковка всего (`--all`) и дамп большой БД могут упереться в лимит памяти — запускайте `php -d memory_limit=-1`.
- **Reverse-proxy**: `site_url()` за прокси может отдать неверный домен/схему — download-ссылка тогда не откроется снаружи.
- **Права на `_packages/`/`_backups/`**: SSH-пользователь и веб-пользователь могут различаться; если папку создаёт SSH-юзер, веб может не отдать файлы (и наоборот).
- **Публичность ссылок**: ссылки на архивы в `_packages/` и бэкапы в `_backups/` публичные (если папки отдаются вебом) — **`_backups/` содержит дамп БД со всеми данными**: удаляйте папки после скачивания (скрипты сами об этом напоминают).

## Безопасность

- Требуется **шелл-доступ**: инструмент исполняет код в контексте пользователя, от которого запущен — давайте доступ только доверенным администраторам.
- **Прямой HTTP-доступ запрещён**: файл отдаёт только справку и завершается (в CLI-режиме он и не исполняется вебом). Держите установленную копию вне docroot.
- **`curl | php` и `eval "$(curl …)"` — supply-chain риск**: код исполняется сразу из сети. Если используете эти способы, пините raw-ссылку по коммиту (`raw/<hash>/...`), а не по ветке.
- **Установленный файл предпочтительнее для прод-сайтов**: аудируется разово и детерминирован — между запусками ничего не меняется.
